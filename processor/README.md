# processor (music-service)

Сервис читает задачи из Kafka-топика `queue`, выполняет DSP-обработку аудио с помощью FFmpeg и публикует результаты в топик `result`. 

Это наиболее CPU-затратный сервис системы. Для увеличения производительности есть возможность масштабировать экземпляры горизонтально.

## Что делает

1. Читает сообщение из `topic:queue` (`job_id` + настройки).
2. Скачивает исходник из S3 (Silo) — вместе с файлом приходит метадата, включающая оригинальное название.
3. Запускает ffmpeg внешним процессом с единым фильтром `rubberband`.
4. Загружает результат в S3 (bucket `job-results`), публикует статус в Redis и сообщение в `topic:result`.
5. Удаляет исходник из S3 сразу после успешной записи результата.

## Идемпотентность

Модель — at-least-once. Offset коммитится после обработки сообщения (`AckMode.BATCH`), а сама обработка (ffmpeg + запись в S3) не транзакционна — при падении процесса между шагами сообщение может прийти повторно.

Защита — проверка статуса в Redis перед стартом обработки: если задача уже `DONE`/`ERROR`, повторная обработка пропускается.

Kafka exactly-once (транзакции) осознанно не используется. Он не защищает от дублирования самой дорогой части (ffmpeg, запись в S3) — она в любом случае вне транзакционной границы Kafka. А транзакция держалась бы открытой всё время обработки и на это время блокировала бы `ws-gateway` от чтения более поздних сообщений в той же партиции.

## Форматы

Поддерживаемые форматы: `mp3`, `wav`, `ogg`, `opus`, `m4a`, `aac`, `flac`, `webm`, `aiff`/`aif`. Обложка альбома сохраняется только для `mp3`/`m4a`/`flac`.

## Масштабирование

Два независимых рычага, не путать между собой:

- **Число инстансов** — `docker compose ... up --scale processor=N`. Даёт эффект только если партиций в `topic:queue` хватает на всех: с `docker-compose-kafka-compact.yml` (1 партиция) активен максимум один consumer, с `docker-compose-kafka-common.yml` (3 партиции) — до трёх параллельно.
- **Конкурентность внутри инстанса** — `spring.kafka.concurrency=${KAFKA_CONCURRENCY:1}`. Существует как рычаг, но не проброшен ни в один compose-файл по умолчанию — чтобы использовать, добавить `KAFKA_CONCURRENCY=<N>` в `environment:` сервиса `processor`.

Ресурсы контейнера ограничены явно (`docker-compose-processor.yml`): `cpus: "1.5"`, `memory: 1G` — работает и без Docker Swarm.

## Внешний процесс ffmpeg

`ProcessBuilder` с `redirectErrorStream(true)` и отдельным потоком на вычитывание вывода — без этого процесс может зависнуть на переполненном pipe-буфере, если ffmpeg пишет в stderr быстрее, чем родитель читает. Таймаут — `waitFor(5, MINUTES)`; при ненулевом `exitValue()` текст ошибки берётся из перехваченного вывода процесса.

## Переменные окружения

Сервис не запускается в одиночку — значения приходят из compose-файлов в корне проекта: S3/Silo (`MINIO_*`), Redis (`REDIS_HOST`/`REDIS_PORT`), Kafka (`KAFKA_BOOTSTRAP_SERVERS`, `KAFKA_CONCURRENCY`).

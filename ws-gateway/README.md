# ws-gateway

WebSocket/STOMP-шлюз — единственный способ для клиента узнать о прогрессе задачи без polling'а. Обращается только к Kafka и Redis за актуальным состоянием.

## Подключение

STOMP-эндпоинт: `ws://.../ws` (через nginx — `/ws`, с апгрейдом соединения).

| Destination | Когда приходит | Payload |
|---|---|---|
| `/topic/job/{job_id}` | задача завершена (`DONE`/`ERROR`) | `JobStateResponse` |
| `/topic/job/{job_id}/queue` | обновилась позиция в очереди | `JobQueueResponse` |

Destination `/topic/*` для клиента `read-only` — заблокировано через `ExternalMessageInterceptor`. Для шлюза `write-only`.

## Откуда берутся данные

Сервис слушает оба Kafka-топика отдельной consumer-группой (`group-id=ws-gateway`), независимой от группы `processor`:

- **Позиция в очереди** — строится как проекция собственного чтения `topic:queue`: при получении сообщения задача добавляется в упорядоченную структуру, при получении события из `topic:result` — удаляется. Позиция = сколько задач впереди ещё не завершено. Пересчитывается заново при каждом завершении (устойчиво к тому, что задачи не всегда завершаются в порядке постановки).
- **Финальный статус** (`DONE`/`ERROR`) — приходит из `topic:result`.

## Фикс гонки подписки

Для решения проблемы с подпиской после завершения работы используется `SubscriptionMessageInterceptor`, читающий актуальный статус из Redis и возвращающий его, если он терминальный (`DONE`/`ERROR`).

## Известное ограничение масштабирования

Сервис спроектирован под MVP как **один инстанс** — по двум независимым причинам:

- **Доставка.** STOMP-брокер in-memory — пушит только в сессии, подключённые к этому же инстансу. Kafka-событие по конкретному `job_id` может прийти на другой инстанс, у которого нужной сессии нет.
- **Позиция в очереди.** Считается в памяти из полного чтения `topic:queue` одной consumer-группой. При нескольких инстансах партиции разъедутся между ними — у каждого будет только часть задач, позиция станет неверной.

Путь эскалации — Redis pub/sub для fan-out между инстансами (решает доставку; для позиции нужно дополнительно вынести расчёт в общее состояние). Осознанно отложено за пределы MVP.

## Переменные окружения

Как и `api`, сервис не запускается в одиночку — все значения приходят из compose-файлов в корне проекта: Kafka (`KAFKA_BOOTSTRAP_SERVERS`), Redis (`REDIS_HOST`/`REDIS_PORT`). Порт сервиса — `8081` (см. `application.properties`).

# api

REST API — точка входа для клиента. Включает в себя приём файла и настроек обработки, статус задачи и скачивание результата. Единственный сервис в системе, куда клиент обращается напрямую (кроме WebSocket, за это отвечает [`ws-gateway`](../ws-gateway/README.md)).

## Эндпоинты

Базовый путь — `/v1/job` (через nginx — `/api/v1/job`). Полный контракт с TypeScript-типами в `Contracts.md` в корне проекта.

| Метод  | Путь                 | Лимит                       | Что делает                                                                                                        |
| ------ | -------------------- | --------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| `GET`  | `/presets`           | —                           | Готовые пресеты (`NIGHTCORE`/`DAYCORE`/`DOUBLE_TIME`/`HALF_TIME`) — скорость + pitch для каждого                  |
| `POST` | `/`                  | 3 req/min                   | Создаёт задачу: сохраняет файл в S3, публикует сообщение в Kafka (`topic:queue`), пишет статус `IN_QUEUE` в Redis |
| `GET`  | `/{job_id}`          | 60 req/min, burst 5 req/sec | Принудительная проверка статуса задачи напрямую из Redis (запасной путь, если WebSocket недоступен)               |
| `GET`  | `/{job_id}/download` | 6 req/min                   | `302`-редирект на presigned S3-ссылку на результат; сам API бинарники не проксирует                               |

Лимиты установлены через `@RateLimit` — кастомную аннотацию на методе контроллера, обрабатываются через `RateLimiterInterceptor` с использованием Bucket4j в качестве token bucket. Ключом является `эндпоинт, IP`, бакеты in-memory на инстансе. Наличие аннотации `@RateLimit` автоматически подхватывается кастомным `OperationCustomizer` и видно прямо в Swagger UI.

## Валидация входного файла

- Лимит размера — 64 МБ (`spring.servlet.multipart.max-file-size`, синхронизирован с `client_max_body_size` в nginx).
- Тип файла определяется по содержимому через **Apache Tika**, не по расширению/имени — так отсекаются переименованные не-аудио файлы. Разрешённые типы аудио — whitelist в `AudioFileService`.
- Настройки обработки (`AudioSettingsRequest`): 
	- `format` — один из `mp3|wav|ogg|opus|m4a|aac|flac|webm|aiff|aif`;
	- `speed` — `0.1`–`3.0`; 
	- `pitchSemitones` — `-12`–`12`.

## Формат ошибок

Единый конверт `ApiResponse { success, message?, validationErrors? }` на все нештатные ответы: `400` (невалидные поля), `413` (файл больше лимита), `429` (превышен rate limit), `404` (задача не найдена).

## Флоу создания задачи

1. Загрузка в S3 (Silo) бакет `client-sources`.
2. Kafka-продюсер публикует сообщение в `topic:queue` **с подтверждением от брокера** в 10 секунд.
3. Если Kafka-публикация не удалась, происходит rollback: файл удаляется из S3, клиенту возвращается ошибка.
4. После успешной публикации сообщения добавляем запись состояния `IN_QUEUE` в Redis. Сбой записи не валит запрос — `force-check` просто не найдёт статус, а для `processor` отсутствие записи считается за `IN_QUEUE` состояние и обработка продолжится.

## Swagger / OpenAPI

Доступен по умолчанию springdoc-путям: `/swagger-ui.html` (UI) и `/v3/api-docs` (спека) — за nginx это `/api/swagger-ui.html` и `/api/v3/api-docs`.

## Переменные окружения

Сервис не запускается самостоятельно вне docker-compose стека — все значения приходят из соответствующих compose-файлов в корне проекта (`docker-compose-silo.yml`, `docker-compose-redis.yml`, `docker-compose-kafka-*.yml`). Полный список — см. `application.properties`: подключение к S3/Silo (`MINIO_*`), Redis (`REDIS_HOST`/`REDIS_PORT`), Kafka (`KAFKA_BOOTSTRAP_SERVERS`).

Как поднять сервис целиком — см. [корневой README](../README.md).
